# Проверки реализации

Среда: Windows 11 (build 26200), Python 3.14.5, Tk 8.6,
ручной запуск с pynput 1.8.2 и six 1.17.0 в отдельном виртуальном окружении.
Репозиторий изучен через авторизованный встроенный браузер GitHub: исходный
`autoclick.py`, README и `.gitignore`; отдельных инструкций репозитория не было.

## Автоматические проверки — выполнены

```console
python -m unittest -v
# Ran 25 tests ... OK; skipped=0
python -m compileall -q .
# exit code 0
```

Все тесты используют подменённую мышь; обработчики глобальной клавиатуры в
автотестах также подменены. Ни один автотест не отправляет ввод на рабочий стол.
Четыре теста связки Tk реально создают и проверяют окно с подменёнными внешними
устройствами. В изолированной среде запуска каталог TEMP/TMP перенаправлялся в
доступный рабочий каталог: системный sandbox TEMP не разрешал файловые операции.

Проверены:

- пустые/ошибочные значения, отрицательные числа, ноль, NaN/Inf, переполнение,
  единицы времени, диапазоны целых и отрицательные координаты;
- успешный Start после ошибочного ввода;
- все 12 комбинаций: 3 кнопки × 2 режима × 2 позиции; ровно 3 повторения;
- отмена задержки без создания контроллера мыши, остановка длинного интервала;
- повторный и конкурентный Start (8 вызывающих потоков), Stop → Start при
  незавершённом вызове мыши, новый запуск после полного завершения;
- исключения инициализации мыши/клика/координат/создания потока и восстановление;
- закрытие во время ожидания, запрет запуска закрытого движка, сохранение
  конечного статуса при позднем Stop;
- F6/F7, подавление автоповтора, синтетический ввод средств доступности,
  ошибки старта/работы listener и его остановка (подменённый backend);
- JSON round-trip, отсутствие сохраняемого состояния запуска, повреждённый
  JSON/кодировка/схема/неподдерживаемая версия, атомарная запись и её отказ;
- отсутствие окон, потоков и импорта pynput при импорте модулей;
- блокировка/разблокировка формы, ошибки полей и счётчики, приоритет Stop,
  сохранение при закрытии и ошибка записи без отказа ручного запуска.

Ожидания контролируются событиями/барьерами, а не случайными задержками.

## Ручная проверка GUI через Computer Use — выполнена

Использован отдельный локальный тестовый стенд, не входящий в приложение:
реальный `App` и `PynputMouse` плюс пустое Tk-окно с подсчётом полученных нажатий.
Клики направлялись только в эту безопасную область.

- Окно, группировка полей, читаемость, видимые Start/Stop/статус/счётчики.
- Прокрутка до координат X/Y: поля доступны, нижняя панель остаётся видимой.
- Start с задержкой 5 с: видимый обратный отсчёт, поля и Start заблокированы.
- Stop во время этой задержки: 0 кликов, статус «Остановлен», поля доступны.
- F6 из другого окна запускает; F7 из другого окна останавливает. При проверке
  F7 успела завершиться одна двойная пара: 1 повторение / 2 клика.
- Повторный F6: конечный запуск `count=3`, `double`, `left`, 500 мс,
  фиксированная позиция (1059, 238). Показано 3 повторения / 6 кликов;
  счётчик целевого окна увеличился с 2 до 8, то есть ровно на 6.
- Повторный запуск приложения восстановил настройки и открылся в «Готов»,
  без автоматического запуска кликов.
- Закрытие через X: процесс завершился. После mainloop диагностический стенд
  подтвердил только `MainThread`, `engine_active=false`, `hotkey_alive=false`.

При проверке обнаружено, что `pynput.keyboard.GlobalHotKeys` версии 1.8.2
игнорирует синтетические события Computer Use. Использован `Listener` с явным
сопоставлением F6/F7 и защитой от удерживания клавиши. Реальный повторный тест
с Computer Use подтвердил исправление.

## Что остаётся проверить пользователю

- Физические F6/F7 на своей клавиатуре: ручная проверка выше использовала
  синтетический ввод Computer Use с фокусом в другом окне.
- Несколько мониторов с разным DPI, перенос между мониторами, конкретные
  режимы Windows 100/150/200%. Системный масштаб при проверке не менялся.
- Реальные правые/средние клики, режим текущего курсора и длительные бесконечные
  запуски в целевых программах: маршрутизация покрыта автотестами, но эти
  сценарии не выполнялись по реальному рабочему столу.
- macOS/Linux/Wayland, другие версии Python и привилегированные окна.
- Как целевая программа распознаёт double-click и ограничивает частоту ввода.

Эти результаты не означают полного тестирования всех платформ и конфигураций.
